# 문제은행 집필·검토 기준

`distribution.mjs`의 공식 네 영역 합계와 사이트 여덟 과목 목표를 기준으로 확충한다. 공식 배점과 객관식 문항 비율은 다르며, 자체 과목 배분을 공식 비율로 표시하지 않는다.

## 데이터와 호환성

- 최종 문제는 `data/{공식영역}.json`에 저장한다. 생성용 집필 자료를 사용하더라도 화면에서 문제를 임의 합성하지 않는다.
- 신규 문항은 사용한 적 없는 ID와 revision 1을 사용한다. 기존 문항의 ID·정답·개정 번호를 유지한다.
- 기존 `id@revision` 저장 키, 과목별 초기화, 보기 순서 섞기, 05·06 호환 주소를 유지한다.
- 질문·보기·정답 의미 또는 보기 순서를 변경하면 revision을 올린다. 의미를 유지하는 설명 보완은 번호를 유지할 수 있다.
- 공식 출제기준 코드는 `syllabus/data.json`의 실제 세부 기준과 대응시킨다. 자체 보충 개념을 공식 문구처럼 쓰지 않는다.

## 문항 품질

- 정답은 하나여야 한다. SQL은 테이블과 NULL·정렬 조건을, 코드는 언어와 초기 상태를, 계산은 단위와 가정을 명시한다.
- 같은 개념도 정의 암기만 반복하지 않고 적용·오류 원인·수정·계산·자료 해석을 구분한다.
- 회사명·변수명·숫자만 바꾼 복사본으로 목표 개수를 채우지 않는다. 계산 연습 변형도 분기·경계·작업 순서 등 확인하는 조건의 차이를 명시한다.
- 보기 모두 같은 질문에 답하는 형태여야 한다. 정답 길이나 전문용어 유무만으로 답이 드러나지 않도록 검토한다.
- 해설은 `핵심 개념:`, `정답인 이유:`, `오답 구분:`으로 작성한다. 실제 오답의 내용과 다른 이유를 설명한다. 계산에는 식과 대입 과정을 제공한다.
- 교재에서 목차·학습목표·관련 본문을 먼저 읽는다. 확인한 교재 페이지는 자체 PDF 뷰어를 연결한다. 구판에 없는 내용은 현재 1차 출처로 확인한다.
- 문항 형식·비율·중복 검사는 자동화하고, 개념과 정답의 타당성은 별도 검토한다. 코드·SQL·계산 결과는 실행 또는 독립 계산으로 대조한다.

## 배포 완료 기준

배분표의 개수와 비율, 전 학습목표의 포함, 기존 데이터 보존, PC·모바일 8과목 및 전체·설명·랜덤 모드, 진도·히스토리·TTS를 확인한 뒤 커밋·푸시한다. 배포 후 공개 데이터의 개수와 실제 문제 풀이를 확인한다.

## 이번 확충의 원본과 검증

- `authoring/concepts.tsv`: 소프트웨어·데이터 개념 판단 106개. 각 행의 상황·개념·설명이 문항 원본이다.
- `authoring/business-additions.tsv`: 비즈니스·윤리·프로젝트 관리·소통 상황 105개.
- `scripts/build-practice-expansion.py`: 입력값을 고정하고 연산의 조합·순서, SQL 조건·집계, 페이지 참조의 반복 관계, 스케줄링 정책, 접근 규칙의 우선순위를 바꾸는 실행 연습을 작성한다. Python에서는 각 단계를 생략했을 때 정답이 달라져야 하며, 접근 정책에서는 실제로 검사하는 경로가 중복된 문항을 제외한다.
- `authoring/execution-proofs.json`: 실행 코드·SQL·초기 상태·예상 결과를 기록한다. `tests/practice-execution.py`가 공개 JSON의 정답과 대조한다. 페이지 교체와 스케줄링은 생성기와 다른 계산 방식으로 검증한다.
- 세부 출제기준마다 문항이 있다는 검사는 범위 누락 검사다. 주제별 학습량이나 실제 출제 가능성이 동일하다는 근거가 아니다. 추가 문항에는 코드·SQL·규칙 해석의 반복 연습 비중이 높다. 화면과 README에서 이를 표시한다.
- 기존 600문항은 데이터 검사에 기록한 SHA-256으로 원본 보존을 확인한다. 이후 기존 문항을 의도적으로 고칠 때에는 개정 정책에 따라 검증 기준도 함께 검토한다.
