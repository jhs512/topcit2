# TOPCIT 객관식 연습

공식 [출제기준 V4.0K](https://jhs512.github.io/topcit2/syllabus/)의 IT비즈니스와 시스템아키텍처 및 정보보안 범위에 맞춘 자체 문제은행입니다. 기존 `topcit`의 100문항 파일을 복제하지 않고 새로 작성했습니다. 공식 기출문제나 공식 검수 자료가 아닙니다.

## 학습 방법

문제 메뉴는 교재와 별도로 여덟 주제를 나란히 표시합니다. 05-01 IT 비즈니스 160문항, 05-02 윤리 20문항, 06-01 프로젝트 관리 110문항, 06-02 테크니컬 커뮤니케이션 10문항이며, 03은 160문항, 04는 140문항입니다. 01·02는 준비 중입니다. 분류 원본은 `shared/learning-subjects.mjs`입니다. 프로젝트 문서(4.4.2.2)를 테크니컬 커뮤니케이션에 배치한 것은 사이트 학습 분류이며 공식 출제기준을 변경한 것이 아닙니다.

기존 05·06 주소는 통합 복습용 호환 화면으로 유지합니다. 같은 `id@revision` 정답 기록을 사용하므로 이전에 맞힌 문제도 새 주제에서 완료로 집계됩니다. 새 주제의 초기화는 해당 주제 문항만 지웁니다.

- **전체모드:** 모든 문항을 페이지 구분 없이 한 화면에 표시합니다. 문항별로 답을 선택해 채점·해설을 확인하고 다시 풀 수 있으며, 주제를 선택할 수 있습니다. 맞힌 기록은 랜덤모드와 공유하지만 전체 목록에서는 문항이 사라지지 않습니다.
- **설명모드:** 모든 문항의 정답과 해설을 페이지 구분 없이 함께 열람합니다. 진도는 바뀌지 않습니다.
- **랜덤모드:** 아직 맞히지 않은 문제를 랜덤으로 불러옵니다. 보기 순서도 섞습니다. 한 번 정답이면 완료되며, 초기화 전까지 다시 출제되지 않습니다. 오답은 남아 있으며 다른 문제가 있으면 바로 같은 문제를 반복하지 않습니다.
- **완료 N개:** 누르면 화면 중앙의 팝업에 현재 주제에서 한 번 이상 맞힌 문제를 최근 완료 순서로 표시합니다. 문제를 누르면 전체모드의 해당 문항으로 이동하며, 해당 주소는 새로고침 후에도 같은 문항을 가리킵니다.
- **이 과목 진도 초기화:** 확인 창에서 실행하면 선택한 과목의 정답 기록을 지웁니다. 다른 과목은 유지합니다.

학습기록은 브라우저 localStorage에 저장됩니다. 같은 기기의 같은 브라우저에서 이어갈 수 있습니다. 기기 간 동기화는 제공하지 않습니다. 브라우저 저장소를 사용할 수 없으면 임시 학습 안내를 표시합니다.

## 출제 범위와 근거

2026-09-15 공식 출제기준 페이지의 ‘전체 펼치기’를 통해 세부 항목을 직접 확인했습니다. `syllabus.mjs`에는 두 영역의 세부 학습목표 57개의 번호·요약 제목과 공식 기준 문장을 저장했습니다. 2026-09-16 공식 문장을 다시 확인했으며, 모든 학습 모드에서 코드와 기준 문장 전체를 표시합니다. 문항의 `syllabus`는 출제범위 대응을 뜻하며, 공식 기관이 해당 문항·정답을 제공했다는 뜻은 아닙니다.

문항 수의 세부 주제별 배분은 자체 연습을 위한 구성입니다. 실제 시험의 주제별 출제 확률이나 배점 비중으로 해석하지 않습니다. 현행 시험에서는 두 과목 모두 서술형이 있고 시스템아키텍처 및 정보보안에는 수행형도 있으므로 이 객관식 문제은행만으로 모든 답안 유형을 연습할 수는 없습니다.

## 문항 유지보수

화면과 문제 데이터는 분리합니다. `data/business.json`, `data/systems-security.json`에 각 300문항을 저장합니다. `id`, `revision`, `area`, `topic`, `prompt`, `options`, `answer`, `explanation`, `syllabus`, `source`를 사용합니다. `answer`는 섞기 전 보기의 0부터 시작하는 인덱스입니다.

새 문항에는 새로운 ID를 부여합니다. 질문·보기·정답의 의미나 보기 순서를 바꾸면 `revision`을 올립니다. 맞힌 기록은 `id@revision`으로 구분하므로 개정 문항은 다시 학습 대상이 됩니다. 단순 오탈자·해설 보완만으로는 개정 번호를 올리지 않아도 됩니다. 삭제 ID는 다른 문제에 재사용하지 않습니다.

질문은 누가 어떤 상황에서 무엇을 하려는지 먼저 설명한 뒤, 묻는 대상을 완전한 문장으로 적습니다. “산출물은?”, “방식은?”처럼 맥락을 생략한 질문을 피합니다. 계산 문제는 대상·단위·가정을 분명히 하고, 약어는 이해에 필요한 경우 풀어 씁니다. 다만 정답인 개념의 정의나 원래 묻던 계산식을 질문에 덧붙여 답을 미리 알려주지 않습니다.

법령 수치·보안 권고처럼 바뀔 수 있는 사실은 공식 자료로 재확인하고, 정답이 하나인지와 오답 선택지의 타당성을 검토합니다. 교재 링크를 추가할 때는 자체 HTML 교재를 이용하고 확인된 교재 페이지 앵커로 연결합니다.

## 검증

`npm test`는 600문항의 스키마·중복·출제기준 범위와 단일 정답 완료·무작위 출제·과목별 초기화 로직을 검사합니다. 자동 검사는 문항 의미와 정답 정확성을 보증하지 않으므로 내용 검토를 병행합니다.

서버가 `http://localhost:4186`에서 실행 중일 때 `npm run test:practice`는 두 화면 폭에서 모드 전환, 정오답, 새로고침 후 진도, 초기화 취소·실행, 전 문항 완료, 마지막 오답 재출제, 저장소 접근 실패를 검사합니다. 다른 주소는 `PRACTICE_BASE`로 지정할 수 있습니다.

`npm run test:practice-all`은 전체 문항 표시, 독립 선택·채점·재시도, 공통 진도, 주제 필터, TTS, 저장 지연 및 저장소 오류를 PC·모바일에서 검사합니다.
