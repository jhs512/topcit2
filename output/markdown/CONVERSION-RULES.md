# IT비즈니스와 윤리 PDF 전사 규칙

## 기준

- 원본 PDF 실제 1~213쪽을 페이지별로 전사한다. 요약, 재해석, 사례 추가, 원문 오류의 임의 수정은 하지 않는다.
- `pages/page-001.md`부터 `page-213.md`까지 실제 PDF 쪽수로 저장한다. 한 페이지에서 끝나지 않는 문장·표도 원본 페이지 경계를 유지한다.
- 각 파일 첫 줄은 `<!-- PDF page: 001 -->` 형식이다. 페이지 번호를 Markdown 제목으로 만들지 않는다.
- 원문 이미지와 원본 열람 링크는 넣지 않는다. 장식·배경·인쇄 머리말·꼬리말은 제외한다. 연락처는 프로젝트 지침에 따라 제외한다.

## 책 전체 제목 계층

| 원문 역할 | Markdown | 예 |
| --- | --- | --- |
| 책 제목 | H1, 합본 전체에서 한 번 | `# IT 비즈니스와 윤리` |
| 로마 숫자로 시작하는 장 | H2 | `## I. IT 비즈니스 개념` |
| 두 자리 번호로 시작하는 절 | H3 | `### 01 IT 비즈니스 개념요약` |
| 가), 나), 다) 항목 | H4 | `#### 가) IT 비즈니스의 정의` |
| 위 항목 안의 원문 소제목 | H5 | `##### 원문 소제목` |
| 그 아래 원문 소제목 | H6 | `###### 원문 소제목` |

- 글자 크기나 페이지 위치에 따라 제목 레벨을 임의로 바꾸지 않는다. 번호 없는 소제목은 현재 소속 항목의 바로 아래 레벨을 따른다.
- 장 도입의 `최근 동향 및 주요 이슈`, `학습 목표`, `핵심 키워드`, `실무 미리보기`는 해당 장 아래 H3이다.
- 목차는 표로 전사한다. 목차에 적힌 장·절 제목을 본문 heading으로 승격하지 않는다.
- 표지의 반복 책 제목·영역명은 일반 문단/굵은 글씨로 둔다. 발행 안내도 문단·표로 전사한다.
- 페이지가 바뀌었다는 이유로 이전 장·절 제목을 반복하지 않는다. 원문 본문에 실제로 다시 나타난 제목만 전사한다. 반복 인쇄 머리말은 제외한다.
- 그림·표 제목은 일반 문단으로 원문 번호·문구를 유지한다. 제목 계층에 포함하지 않는다.

## 본문·표·도식

- 원문 문구와 읽기 순서를 보존한다. 줄바꿈은 문단 단위로 정리하되 문장과 정보는 삭제하지 않는다.
- 단순 표는 Markdown 표, 병합 셀과 다단 머리글이 있는 표는 HTML table로 작성한다. 표 셀의 나열은 `<br>`를 쓸 수 있다.
- 내용 도식은 원문의 노드·문구·방향·연결을 확인할 수 있을 때만 Mermaid로 옮긴다. 새로운 관계나 해설은 추가하지 않는다.
- 표현할 수 없는 그림은 생략하고 해당 위치에 `<!-- 생략: 그림 번호 또는 제목 / 표현 불가 요소 -->`를 남긴다. 그림 내부의 읽을 수 있는 문구를 유지할 경우 원문의 묶음을 보존하고 관계를 추정하지 않는다.
- 원문에서 확인할 수 없는 글자는 추측하지 않고 `[판독 불가]`로 표시한다. OCR은 초안이며 원본 렌더와 대조한다.
- 원문의 기존 오탈자·중복 번호는 임의 수정하지 않는다. 불가피한 전사 주석은 HTML 주석으로 구분한다.

## 합본·검증

- 수정 원본은 개별 페이지 파일이다. 합본은 001~213 번호순 단순 연결로만 생성한다.
- 합치기 전 213개 파일, 페이지 번호 중복·누락, 이미지·원본 링크 미삽입, heading 계층, 표 열 수, Mermaid 문법을 확인한다.
- 일부 페이지 미완료 상태를 완성본으로 표시하지 않는다.

## 사용자 승인 예외

- 그림 2의 A~E 표기는 읽기 편하도록 `프로세스 A`~`프로세스 E`, 결합 표기는 `프로세스 A + IT` 형태로 표시한다.
