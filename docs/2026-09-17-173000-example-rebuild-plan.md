# 핵심노트·사례 설득력 전수 개편

## 요청과 범위

학교·고등학생에게 익숙한 소재를 우선하던 기준을 수정한다. 독자가 업무 경험이 없어도 이해하도록 설명하되, 개념의 필요성이 자연스럽게 드러나는 실제 업무 상황을 선택한다. 핵심노트 8과목 160개(도입·본문 속 예시·질문 포함)를 먼저 검토·수정·검증·푸시하고, 사례 모음 160편을 다음 단계에서 검토·수정·검증·푸시한다. 기존 ID·주소·교재 근거·학습기록은 유지한다.

## 판정 기준

1. 목적: 이 사례로 설명할 개념과 판단이 한 문장으로 특정되는가?
2. 필연성: 문제가 그 업무에서 자연스럽게 생기는가? 간단한 대안으로 피해가 사라진다면 그 대안의 한계까지 설명했는가?
3. 구체성: 누가 언제 무엇을 못 하며 어떤 손실·오류·대기가 생기는가?
4. 인과: 선택한 조치가 문제 원인을 직접 바꾸는가? 조치 전후의 차이가 보이는가?
5. 정확성: 결과를 과장하지 않고 전제·대가·남은 한계를 설명하는가? 다른 개념의 사례를 억지로 붙이지 않았는가?

각 항목을 유지·보강·교체로 기록하고 근거를 남긴다. 유지도 개별 검토한다. 학교 소재의 단순 단어 치환, 모든 예시를 같은 업종으로 통일, 숫자만 추가, 자동 검사 통과를 문장 품질의 증거로 삼는 방식은 사용하지 않는다.

## 작업 순서

1. `books.mjs`가 지정한 여섯 교재의 목차·학습목표·대응 단원 본문과 320개 콘텐츠의 현행 원고를 읽는다.
2. 핵심노트: `shared/textbook-alignment.json`의 완성 원고와 `practical/subject-introductions.mjs`를 수정한다. 예시만 바꾸고 설명·질문에 이전 상황이 남지 않도록 함께 대조한다. 판정 기록은 `docs/example-review-notes.json`에 남긴다.
3. 핵심노트 빌드, 기존 핵심노트·핵심 콘텐츠 검사와 PC/모바일 검증 후 1차 커밋·푸시.
4. 사례: `reading/expanded-cases.mjs`, `reading/case-lessons.json`, 기존 11편 원고·기획, 교재 연결의 `caseReason`을 함께 검토한다. 목적·상황·행동·결론이 일치하게 수정하고 `docs/example-review-cases.json`에 기록한다. 실사례는 기존 공식 근거를 확인하고 사건·해석을 구분한다.
5. 사례 빌드·스키마·160편 연결·PC/모바일 검사 후 2차 커밋·푸시. 기존 11편 원고를 수정하면 `topcit/reading`의 대응 원고·기획도 동기화한다.
6. 공개 페이지에서 개편 원문 반영과 핵심 동선을 확인하고 이 문서에 결과를 기록한다.

## 제외 및 검증 원칙

현재 미추적된 문제은행 균형 진단 파일과 `topcit`의 교재 변환 작업은 별도 작업이므로 커밋에 포함하지 않는다. 시험 일정·규정은 이번 변경 범위가 아니다. 교재 원문을 사례에 맞게 고치지 않는다. 가상 사례의 수치와 결과는 교육용 설정임을 유지한다. 교재 링크를 새로 쓰거나 수정할 때는 확인한 페이지의 자체 PDF 뷰어 주소를 사용한다.

## 실행 기록

- 원본 위치 확인: `topcit2` main, origin `jhs512/topcit2`. 핵심노트 160개, 기존 사례 11편 + 추가 사례 149편.
- 1단계 완료: 핵심노트 160개 개별 판정. 유지 68개, 보강 78개, 교체 14개. 과목 도입과 본문 속 학교 상황, 확인 질문도 함께 수정했다. `docs/example-review-notes.json`에 목적·판정 이유·교재 위치 기록.
- 1단계 검증: `npm run build:practical`, `npm run test:core` 통과. `SITE_BASE=http://127.0.0.1:4197/ npm run test:practical`에서 1440·390·320px, 8과목·160개 앵커·가로 넘침·TTS 검사 통과. 자동 검사는 누락과 화면 회귀를 확인하며 설득력은 별도 개별 원고 검토로 판단했다.
- 2단계 예정: 160편 사례의 사건·행동·결론과 교훈·교재 연결 문장 전수 대조.
