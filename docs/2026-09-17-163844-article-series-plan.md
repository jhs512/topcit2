## 요구와 범위

article 대메뉴와 8과목별 긴 글 한 편씩을 추가한다. IT를 조금 아는 고등학생이 제로부터 시간순으로 따라간다. 교재와의 연결은 요구하지 않는다. 가상의 주문 서비스 ‘한끼픽’을 배경으로 사용하고, 인물·규모·시간·관측 수치는 설명용 설정임을 밝힌다. 실제 제품 동작은 공식 문서로 확인한다.

기술 이름을 먼저 나열하지 않는다. 상황 → 관측한 문제 → 원인 확인 → 비교한 선택 → 실행 → 새로 생긴 문제 순서로 장면을 쓴다. 모든 도구를 반드시 도입해야 하는 성장 단계로 오해하지 않도록 도입하지 않는 조건도 설명한다. 전문용어는 첫 등장 자리에서 뜻을 풀고, 대화는 문제와 판단을 드러낼 때 사용한다.

## 구현

- `article/content/*.md`: 집필 원본, `article/catalog.mjs`: 8개 글 메타데이터.
- `scripts/build-articles.mjs`: Markdown을 정적 HTML로 생성. 목록 → 과목별 글. 모든 글이 실제 완성된 후 공개 메뉴에 연결.
- `article/styles.css`, `article/reader.mjs`: 목차·진행 표시·표 가로 스크롤·그림 확대·다크모드·TTS 범위.
- Mermaid UML은 빌드 시 SVG로 렌더링하여 브라우저 외부 CDN 의존 없이 표시. 확대창은 키보드 닫기와 원위치 포커스 지원.
- archify 구성도 1개를 별도 확대 탐색 자료로 제공. 본문은 한국어, 도구 자체의 고정 뷰어 UI와 HTML lang은 지원 범위상 영어임을 명시.
- `shared/site-navigation.mjs`에 article 메뉴와 8개 과목을 추가하고 홈 카드·README를 갱신. 메뉴 공간·기존 링크·진도 유지.

## 검증 및 게시

8편의 시간순 흐름과 용어·원인·선택·부담을 읽어 검토한다. 코드로 항목 수·목차·그림·표·내부 링크·SVG 생성 실패를 검증하고 PC 1440px 및 모바일 390/320px에서 렌더링, 메뉴, 다크모드, 그림 확대, 키보드, TTS를 확인한다. 기존 문제·교재 파일은 변경하지 않는다. 기존 별도 문제 배분 작업 4개 파일을 제외하고 커밋·게시한다. 공개 Pages 성공과 실제 글·그림 반영을 확인하고 결과를 여기에 기록한다.

## 실행 결과

8편 모두 집필했다. 한 편당 7~12개 시간순 장으로 구성하고, 관측→원인→선택→부담을 연결했다. 시스템아키텍처는 약 24분, 나머지 글은 약 10~12분의 예상 읽기 분량이다. 이 시간은 원고 길이로 추산한 안내이며 독자 시험 결과가 아니다.
