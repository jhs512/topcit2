- 여덟 주제의 핵심노트 160개와 사례 160편을 여섯 교재와 대조한다. 윤리를 먼저 점검한다.

### 근거 대응 및 기록 방식
- `shared/textbook-alignment.json`: 노트 ID(주제/번호)에 대응하는 교재번호·PDF페이지·단원/개념·교재 요약·사례 연결 이유. 기존 비즈니스 사례는 별도 ID 대응을 둔다.
- 범용 원리를 다른 맥락에 적용한 경우에는 '교재 원리의 실무 적용'으로 표시하고, 교재에 그대로 없는 구현/통계/운영 방법은 연결 설명에 한계를 적는다.
- 참조한 페이지의 본문을 확인한 뒤 기록한다. 다른 교재가 직접 근거인 경우 올바른 교재번호를 쓴다. 제목 키워드 일치만으로 근거를 확정하지 않는다.
- `docs/textbook-alignment-audit.md`: 320개 항목의 개별 대응 및 수정 기록. 추가 학습이 필요한 목표도 주제별로 정리한다.
- 학생 화면: 각 노트/사례에 '관련 교재 내용', 교재명, 단원/개념, 짧은 요약/연결 이유, 확인한 PDF 링크. 기존 교훈 구조는 유지한다.
- 주제별 실무 선정 20개를 교재 전체 요약이라고 바꾸지 않는다. 누락된 이론 목표는 별도 '교재에서 함께 확인할 내용' 안내에 짧은 개념 설명과 정확한 위치를 제공한다.

### 우선순위와 단계별 검증
1. P1: 잘못된 개념 대응/위험한 단정/참조 오류를 먼저 바로잡는다. 윤리→소통→관리→비즈니스→개발→데이터→아키텍처→보안 순서로 대조한다.
2. P2: 각 항목의 개념·사례 대응과 학생용 근거 표시를 완성한다. 목록 ID 및 기존 링크를 보존한다.
3. P3: 학습목표 대비 부족한 이론을 함께 읽는 안내로 보완하고 전 주제의 균형과 중복을 재검토한다.
4. 생성 전: 160개 노트·160개 사례 대응 누락, 범위 밖 페이지, 빈 근거와 잘못된 교재 번호를 검사한다.
5. 생성 후: 원고/생성 일치, 사례 필수 구획/실제·가상 표시, PDF 링크 수·주소·페이지, 기존 사용자 수정 보존을 검사한다.
6. 브라우저: 모든 주제의 핵심노트와 사례 표본은 PC/모바일, 전체 160개 사례는 DOM 검사. 근거 제목·연결 설명·링크·TTS 및 가로 넘침 확인. PDF 표/도식이 연결 판단의 핵심인 경우 실제 PDF 페이지를 렌더링하여 비교한다.
7. 종료 보고: 실제 확인 범위와 수정/재작성 수, 빌드·테스트 결과, 보완했지만 전체 시험 준비를 대신하지 않는 범위를 명확히 적는다.

계획 상세화 완료. 윤리 2개 사례는 초기 조사 중 수정 초안을 만들었으며, 전체 계획이 마련된 뒤 각 항목 본문 확인과 검증을 계속한다. 현재 배포하지 않았다.

## 추가 보강 원칙
- 핵심노트는 출처 링크나 응용 표시만으로 정합성을 확보했다고 판단하지 않는다. 본문에서 교재 원개념을 학생이 이해할 수 있게 먼저 설명하고 기존 예시·확인 질문으로 연결한다.
- 일반 실무 조언 중심이어서 교재 학습목표와 거리가 먼 항목은 제목·설명을 교재 개념 중심으로 수정한다. 분석의 인과 해석·표본 대표성 같은 확장 내용은 관련 원개념을 대체하지 않도록 재구성한다.
- 항목별 본문 보강 여부와 대표 수정 전후를 점검표와 최종 보고에 남긴다.


## 실행 결과

- 여섯 교재의 목차·학습목표와 관련 본문 대조를 완료했다. [항목별 점검표](textbook-alignment-audit.md)에 핵심노트 160개와 사례 160편의 교재명·단원·검증 페이지·연결 이유·수정을 기록했다. 교재 전체 모든 문장을 정독했다는 뜻은 아니다.
- 핵심노트 160개 본문을 교재 원개념 중심으로 보강하고 제목 49개를 수정했다. 요구사항 추출, ACID, 레이어/티어, CIA, ISP, 획득가치, 3P 같은 원개념이 설명 앞에 드러나도록 했다. 일반 조언에 링크만 덧붙이는 방식으로 끝내지 않았다.
- DATA-08·16에 해당하는 분석 노트는 서술/예측 분석과 데이터 품질을 먼저 설명하고 인과 해석·표본 대표성은 추가 해설로 구분했다. 비즈니스 11번 노트는 ROI/NPV, 프로젝트 15번 노트는 PV/EV/AC의 수치 예시로 설명했다. SS/FF 관계를 반드시 동시 시작/완료로 오해하지 않도록 정리했다.
- 가상 사례 6편의 상황·행동/결과를 수정했다. ETH-18과 SEC-04는 노트와 어긋난 주제를 다시 썼고, ETH-12는 동의 대상을 분명히 했으며 SEC-17은 서명·출처 검증, ARCH-13은 큐의 접수/처리 분리, PM-15는 획득가치 비교를 실제 이야기에서 다루게 했다.
- 모든 320개 항목에 학생용 ‘관련 교재 내용’을 표시했다. 각 사례는 구체적인 연결 이유도 표시한다. 기존 비즈니스 11편은 별도로 대응시켜 BIZ-11을 같은 번호의 ROI 노트에 잘못 연결하지 않았다.
- 학습목표 대비 부족했던 알고리즘·정규화·SQL·OS/CPU·암호/PKI·WBS/CPM 등 35개 추가 학습 항목에 설명·확인 질문·페이지를 제공했다. 20개 노트와 35개 안내가 교재 전체를 대신하지 않는다는 범위도 밝혔다.
- 기준 원본과 TOPCIT2 사본의 고유 근거 페이지 129곳이 일치한다. [페이지 해시 기록](textbook-page-evidence.json)에 추적 근거를 남겼다. 정규화·AI 윤리 원칙·획득가치 표는 원본 PDF를 렌더링해 확인했다.
- 원고와 공통 생성기를 수정해 핵심노트·사례 HTML과 생성 Markdown을 재생성했다. 지정 PDF 뷰어 링크를 허용하도록 검사기를 수정했고, README·저작 지침의 이전 HTML 전용 설명도 맞췄다. 원본 topcit/reading의 동명 원고·계획은 URL 외 차이가 없음을 확인한 뒤 동기화했다.
- 실제 사례 4편의 외부 사건 근거, 기존 비즈니스 11편 본문·결론, 전체 ID·URL·교훈 박스와 실제/가상 구분을 보존했다. TTS는 기본 OFF이고 출처 이름·URL·메타 문구는 읽기 대상에서 제외했다.
- 앞서 요청한 3주/21시간, 복습 항목 삭제, ‘핵심 노트와 사례 모음을 읽습니다’, 이력서 기준 표현·지원자 관리 저장소 링크 삭제를 유지했다. CSS·다크 모드·문제은행은 변경하지 않았다.

### 배포와 범위

커밋·푸시·배포는 하지 않았다. 변경은 로컬 작업본에서 검증했다. 교재의 원개념과 자체 설명·실무 확장을 구분했으며, 실제 사건의 새로운 사실 확인이나 최신 법령 해설을 추가하는 작업은 하지 않았다. 35개 추가 학습 항목도 전체 교재·시험 대비를 대체하는 목록으로 제시하지 않는다.


완료 상태: 계획 → 전체 대응·본문 보강 → 생성 → 콘텐츠/브라우저 검증까지 완료. 이 계획의 미완료 실행 항목은 없다. 배포는 이번 실행 범위에 포함하지 않았다.


## 후속 배포 승인

1차 보강·검증 완료 뒤 사용자가 ‘내가 푸시하라고 하지 않아도 바로바로 푸시해’라고 지시했다. 이에 따라 이번 승인된 변경은 공개 저장소 `jhs512/topcit2`의 `main`에 커밋·푸시하고 Pages 배포와 공개 화면을 확인한다. 원본 `jhs512/topcit`에는 동기화한 원고·계획 두 파일만 별도로 반영한다. 두 저장소의 공개 상태, 원격 주소, Pages의 `main` 루트 배포 설정과 원격 동기화를 확인했다. 이 절차는 위 1차 완료 시점의 미배포 상태 이후에 수행하는 후속 작업이다.
