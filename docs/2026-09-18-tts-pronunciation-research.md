# 한국어 TTS 수학·기술 표기 조사

확인일: 2026-09-18. 공식 규격·언어 문서에 근거한 구현 권고이며, 특정 브라우저의 실제 음성을 청취한 결과는 아니다. 한국어 독음은 아래 사용자 지정과 사이트 편집 기준을 따른다. 공식 문서가 이 한국어 독음을 표준으로 지정했다는 뜻은 아니다.

## 확인한 사실과 적용 권고

| 확인한 사실 | 이 사이트에 적용할 권고 |
|---|---|
| Web Speech API의 `SpeechSynthesisUtterance.text`는 일반 문자열 또는 완전한 SSML 문서를 허용한다. SSML 전체 또는 일부를 지원하지 않는 엔진은 미지원 태그를 제거하고 내용을 읽도록 규정한다. | “브라우저는 SSML을 지원하지 않는다”라고 단정하지 않는다. 공통 구현은 읽기 전용 한국어 문자열을 만들어 전달하며, 특정 SSML 태그의 지원에 의존하지 않는다. [Web Speech API §4.2.4](https://webaudio.github.io/web-speech-api/#utterance-attributes) |
| 사용할 수 있는 음성 목록과 기본 음성은 사용자 에이전트에 따라 달라진다. `lang`과 `voice`는 별도 속성이다. | `ko-KR`과 사용 가능한 한국어 음성을 선택한다. 변환 문자열 검사와 실제 청취 검사를 구분한다. 같은 한글 문자열도 모든 기기에서 똑같은 음성으로 들린다고 보장하지 않는다. [Web Speech API §4.2.2–4.2.4](https://webaudio.github.io/web-speech-api/#speechsynthesis-methods) |
| HTML의 `sup`·`sub`는 의미를 가진 위첨자·아래첨자를 나타낸다. 수학 외에도 약어 등에 쓰인다. | DOM을 곧바로 `textContent`로 평탄화하면 `n<sup>2</sup>`와 `n2`를 구분하지 못한다. 추출 전에 구조를 보존하되 모든 위첨자를 지수로 단정하지 않는다. [HTML Standard §4.5.19](https://html.spec.whatwg.org/multipage/text-level-semantics.html#the-sub-and-sup-elements) |
| MathML의 `msup`·`msub`는 밑과 첨자를 분리하고, `mfrac`는 분자와 분모를 별도 자식으로 표현한다. | 구조를 읽을 때 지수·첨자·분수 순서를 보존한다. 한국어 분수 독음은 분모를 먼저 읽어야 하므로 문자열 이어 붙이기로 대체하지 않는다. [MathML Core §3.3.2](https://w3c.github.io/mathml-core/#fractions-mfrac), [§3.4.1](https://w3c.github.io/mathml-core/#subscripts-and-superscripts-msub-msup-msubsup) |
| MathML 4는 수학 표기의 문맥 의존성과 모호함을 설명하고, 저자의 의미를 전달하는 `intent`를 다룬다. 실제 음성 구성은 시스템별로 달라질 수 있다. | 기호 하나에 발음 하나를 일괄 대응하지 않는다. 모호한 식에는 작성자가 지정하는 읽기 문구를 우선한다. MathML `intent`만 추가하면 Web Speech가 자동으로 해석한다고 가정하지 않는다. [MathML 4 §5](https://www.w3.org/TR/mathml4/#chapter_intent) |
| Python에서 `^`는 비트 XOR이고 `**`는 거듭제곱이다. `%`는 수치의 나머지 연산 또는 문자열 서식에 쓰이며, `/`와 `//`는 다른 연산이다. | 코드의 `n ^ 2`를 수학의 “엔제곱”으로 읽거나 `x % 2`를 퍼센트로 읽지 않는다. 코드와 수학 설명의 변환 경로를 구분하고 긴 연산자를 먼저 처리한다. [Python 표현식 §6.5–6.9](https://docs.python.org/3/reference/expressions.html) |
| CIDR에서 IPv4 주소 뒤 `/24`는 유효한 네트워크 비트 수를 나타낸다. | `192.168.0.0/24`를 분수로 읽지 않는다. 주소·날짜·URL·파일 경로를 먼저 보호한 뒤 제한된 수식에만 나눗셈 변환을 적용한다. [RFC 4632 §3.1](https://www.rfc-editor.org/rfc/rfc4632#section-3.1) |

## 반드시 유지할 사용자 지정

| 화면 표기 | 음성용 문자열 |
|---|---|
| `logn`, `log n` | 로그엔 |
| 독립 수학 변수 `n` | 엔 |
| `nlogn`, `n log n` | 엔로그엔 |
| 수학 문맥의 `n²`, `n^2` | 엔제곱 |
| 수학 문맥의 `n³`, `n^3` | 엔세제곱 |
| 수학 문맥의 `2ⁿ`, `2^n` | 이엔제곱 |

독립 변수 규칙은 `login`, `nan`, URL, 파일명 속 문자에 적용하지 않는다. `2ⁿ` 독음은 이 사용자의 명시적 요구이며 일반적인 수학 용어 규정으로 확대하지 않는다.

## 구현 및 검증 우선순위

아래는 조사 결과를 바탕으로 한 구현 제안이다.

1. 화면·복사 원문은 유지하고 TTS에 전달하는 문자열만 정규화한다. 사이트 공통 변환기를 사용해 문제·교재·핵심노트·사례·심화수업 사이의 발음 차이를 줄인다.
2. 비교 기호(`≤`, `≥`, `≠`, `≈`), 명확한 산술 기호(`×`, `÷`, `−`), 제곱·세제곱·루트·무한대와 복잡도 표현부터 처리한다. 수식의 피연산자 순서와 괄호 범위를 지킨다.
3. 집합 기호·논리 기호는 집합·논리 문맥에서 읽는다. `|`는 절댓값·조건부 확률·비트 OR 등이 가능하고 `!`는 계승·부정·문장 부호가 가능하므로 전역 치환하지 않는다.
4. 단위는 숫자와 결합한 토큰으로 처리한다. `MB`와 `Mb`, `ms`와 `m`을 구분하며 일반 단어 속 영문을 바꾸지 않는다. 약어는 검증한 사전 항목만 바꾼다.
5. 코드에서는 문자열·주석·식별자를 보호한다. `==`, `!=`, `<=`, `>=`, `//`, `**`, `<<`, `>>` 등은 원래 연산을 잃지 않게 읽는다. 정확히 해석하기 어려운 코드는 기호 이름으로 읽는 편이 잘못된 수학 의미를 부여하는 것보다 안전하다.
6. 자동 검사에는 변환 성공뿐 아니라 보존 사례를 넣는다: `2026-09-18`, `2026/09/18`, `https://example.com/a/b`, `192.168.0.0/24`, `SHA-256`, `C++`, `C#`, `x % 2`, `n ^ 2`, `a != b`, `login`, `n2`.
7. DOM 검사에는 `n<sup>2</sup>`, `log<sub>2</sub>n`, MathML 분수, 하이라이팅된 코드의 여러 `<span>`을 포함한다. 원래 화면 문자열이 유지되는지와 최종 음성 입력을 함께 확인한다.

복잡한 중첩 수식과 그림 속 수식은 단순 정규식만으로 해석을 보장할 수 없다. 명시적 읽기 문구 또는 구조를 이해하는 별도 수식 처리기가 필요한 범위로 남긴다. 배포 보고에서는 자동 검사로 확인한 음성용 문자열과 실제 기기에서 청취한 범위를 나누어 기록한다.
