# 사례 작성 형식

`it-business-stories.md`가 본문의 기준 원본이다. HTML은 직접 편집하지 않는다. 개념·교훈을 바꿀 때는 같은 ID의 계획도 먼저 검토한다.

문서 맨 처음에는 `<!-- case-schema: 2 -->`를 한 번 쓴다. 각 사례는 아래 순서를 따른다. `들어가기 전에`만 생략할 수 있으며, 참고가 없으면 참고 구획도 생략한다.

```markdown
## BIZ-11 · 사례 제목

유형: 가상 이야기
교재 개념: 관련 개념

### 이 글에서 배우는 교훈

추상적인 문장: 교재에서 확인한 일반 원리를 한 문장으로 풀어 쓴다.
근거: [I.01 비즈니스와 IT의 연계 · PDF 20쪽](https://jhs512.github.io/topcit2/textbook/05/#page-020)
구체적인 문장: 그 원리를 이 사례에 적용한 교훈을 한 문장으로 쓴다.

### 들어가기 전에

필요할 때만 쓰는 배경·용어 설명.

### 본문

사건과 선택, 결과를 설명하는 본문. 근거가 필요한 문장은 번호로 연결한다. [1](#BIZ-11-ref-1)

### 결론

본문에서 도출한 판단. 교훈을 그대로 반복하지 않는다.

### 참고

필요하면 교재와 사건의 관계를 설명하는 기존 문단을 둔다.

1. [확인한 교재 위치](https://jhs512.github.io/topcit2/textbook/05/#page-020)
```

교훈·본문·결론은 필수이며 비어 있을 수 없다. 구획 제목은 예시와 정확히 맞춘다. 유형은 `가상 이야기`, `실제 사례`, `실제 성공 사례` 중 하나이며 뒤에 ` · 출처의 사건명·연도`를 붙일 수 있다. 본문 소제목이 필요하면 4단계(`####`) 이하를 쓴다. HTML이나 옛 사전설명 마커를 삽입하지 않는다.

교훈에는 `추상적인 문장:`, `근거:`, `구체적인 문장:`을 위 순서로 각각 한 줄씩 붙여 쓴다. 두 문장과 근거는 모두 필수다. 두 문장은 일반 텍스트로 쓰며 같은 문장을 반복하지 않는다. 근거는 `단원명 · PDF N쪽` 링크로 쓰고 페이지 숫자를 HTML 앵커와 일치시킨다. 추상적인 문장은 원문 인용이 아니라 교재 개념을 풀어 쓴 원리로 표시한다. 개념은 `books.mjs`의 source가 가리키는 Markdown에서 목차·학습목표·관련 단원 본문을 읽고 확인한다. 원리의 근거 위치가 확인되기 전에는 게시하지 않는다.

교훈의 원리 근거 링크 외 출처 URL은 참고 목록에 두고 본문에서는 `[번호](#사례ID-ref-번호)`로 연결한다. 번호는 1부터 연속이며 각 번호는 실제 목록 항목과 일치해야 한다. 교재 링크는 확인한 자체 HTML 교재 위치를 사용한다. 실제 사건의 외부 근거는 그대로 유지한다.

## 생성과 검사

- `npm run test:case-schema`: 필수·선택·순서·중복·메타데이터·참고 대상 검사 테스트.
- `npm run build:cases`: 전체 원본과 근거 페이지의 실제 존재를 먼저 검증하고 모든 사례를 공통 렌더러로 생성. 실패 시 파일명과 사례 ID를 확인한다.
- 로컬 4186 서버에서 `npm run test:cases`: PC·모바일의 교훈→선택 도입→본문→결론 흐름과 이동 확인.
- `scripts/case-schema.mjs`: 명시적 스키마, 파서·검증기, 공통 렌더러. `scripts/build-cases.mjs`: 목록과 개별 페이지 생성.

결론은 공통 박스로 표시되고, 선택 도입은 기존 사전설명 박스로 표시된다. 참고 영역은 이야기 바깥에 둬 이야기의 마지막 구획이 항상 결론이 되게 한다. TTS용 `tts-readable` 클래스는 렌더러가 의미 단위에 부여한다. TTS는 첫 방문 기본 OFF이며 공통 상단 버튼에서 방문자가 켜고 끈다. 원고의 `tts-readable` 표시는 선호 상태와 관계없이 유지한다.

## 원본 동기화와 이번 이행

`topcit/reading`의 원고·계획과 이 저장소의 동명 원고·계획을 함께 수정해 같은 내용으로 유지한다. 게시·검증 코드는 `topcit2`에서 관리한다.

v2에서는 기존 교훈을 구체적인 문장으로 유지하고, 교재 기반 추상적인 문장과 원리 근거를 추가한다. 기존 도입·본문·결론·참고는 보존한다. 사례 목록에는 기존과 같이 구체적인 문장을 표시한다. CRM 문장은 BIZ-09에서만 사용한다.

공통 렌더러는 제목·두 문장·근거를 모두 하나의 `.case-lesson` 박스 안에 둔다. 내부 필드명인 “추상적인 문장”과 “구체적인 문장”은 학생 화면에 표시하지 않는다. 원리는 바로 표시하고, 사례 적용 문장 앞에는 “구체적으로는”을 붙여 한 문단으로 표시한다. 승인된 문장 자체는 바꾸지 않는다. 사례별로 별도 박스를 만들거나 밖에 배치하지 않는다. PC·모바일 10편 DOM 검사에서 동일 컨테이너의 자손 관계와 실제 박스 경계 안의 배치를 확인한다.

10편 이행 시 BIZ-01·05·07은 기존 명시적 판단 문단을 결론으로 옮겼고, 나머지 7편은 기존 마지막 개념 설명 문단을 사용했다. 새 주장이나 사건을 추가하지 않았다. 교훈·메타데이터·산문 문단 전체와 출처 URL을 이행 직전 원고와 대조했고, 구획·표제·인용 배치 외 내용이 같음을 확인했다. 시리즈 전체 마무리는 개별 사례에서 분리해 목록 끝에 표시한다.
