각 구성 요소가 무엇을 책임지고 어떤 약속으로 연결되는지 분명해야 합니다.

핵심노트를 바탕으로 만든 가상 이야기입니다. 실제 사건이나 검증된 성과가 아닙니다.
근거: 경계와 의존성 — 한 부분의 변경이 번지지 않게 한다 · 핵심노트 3

구체적으로는 팀은 회원 정보의 변경 책임을 정하고 공개된 조회·수정 경로를 사용하게 했습니다.

본문

여러 서비스가 회원 테이블의 열을 직접 읽고 수정했습니다. 회원팀이 구조를 바꾸자 다른 서비스들이 동시에 실패했습니다.

팀은 회원 정보의 변경 책임을 정하고 공개된 조회·수정 경로를 사용하게 했습니다. 전환 중 기존 사용처를 확인하며 직접 접근을 줄였습니다.

결론

경계는 시스템을 나눠 배포하는 것만으로 생기지 않았습니다. 다른 팀이 의존하는 약속과 데이터 변경 책임을 명확히 해야 합니다.
