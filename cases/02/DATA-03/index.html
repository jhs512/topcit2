관련 교재 내용

데이터 이해와 활용 · IV. 데이터 모델링 · 기본키와 식별

기본키는 표의 각 행을 중복 없이 구별하는 값입니다. 고객 이름처럼 겹치거나 바뀌기 쉬운 값보다, 대상과 안정적으로 연결되는 식별값을 선택합니다.

이 사례에 적용한 내용: 동명이인과 번호 변경을 이름·전화번호로 억지 연결하지 않고 고객 번호로 확인한 기록만 결합했습니다.

본문

분석팀이 고객 이름으로 매장과 온라인 주문 파일을 연결하자 동명이인 두 사람의 구매가 합쳐졌습니다. 이를 고치려고 전화번호로 연결했더니 번호를 바꾼 한 사람이 두 고객으로 나뉘었습니다. 같은 원본에서 연결 방법에 따라 고객 수가 달라졌습니다.

팀은 회원 가입 때 발급한 고객 번호로 확인 가능한 기록을 연결하고, 주문 번호로 거래를 구별했습니다. 예전 파일처럼 공통 고객 번호가 없는 자료는 이름만으로 강제 결합하지 않고 확인 대상으로 분리했습니다. 연결 전후의 고객 수와 주문 금액도 대조했습니다.

결론

식별자가 없는 과거 자료가 자동으로 모두 해결된 것은 아닙니다. 무엇을 한 사람으로 판단할 근거가 있는지 구분하니, 불확실한 연결을 확정 사실처럼 사용하는 일을 줄일 수 있었습니다.
